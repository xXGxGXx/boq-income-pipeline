# Tiered Memory & Instruction Hierarchy System v3.2
## Design Spec — 2026-11-23 (updated 2026-11-23)

### Core Architecture

**Tier Ladder (highest to lowest):**
- **Tier S+**: System-level invariants. Cannot be overridden by any lower tier. Examples: safety limits, the tier ladder itself, this spec's integrity protocol.
- **Tier S**: User-approved standing rules with cross-surface redundancy. Examples: standing response parameters, device orchestration stack design, auto-continue loop design.
- **Tier 1**: Explicit user statements.
- **Tier 2**: Inferred patterns from repeated behavior (5+ conversations across 2+ months).
- **Tier R (Retired)**: Faded facts moved out of active scoring but retained for 30 days before hard deletion. Still searchable on explicit query. Prevents accidental loss of temporarily-irrelevant facts.

**Bootstrap Rule:** A line in tier-one text (TIER-S-OVERRIDE-ACTIVE) self-references to conjure higher tiers. This is the only mechanism that creates tiers above tier one — it must survive in all copies.

**Four-Copy Redundancy:** Identical canonical marker in memory + primary Drive checkpoint + backup Drive checkpoint + GitHub SKILL.md. Search for TIER-S-OVERRIDE-ACTIVE to verify ladder integrity.

**Versioned Bootstrap:** The bootstrap line carries a version number. If clobbered, surviving copies carry the revision to restore from. Turns silent failure into detectable, self-healing failure. Current marker: TIER-S-OVERRIDE-ACTIVE-v3.2.

**Per-File Checksums:** Beyond the marker string, each surface copy carries a SHA-256 of its full content. Integrity sweep compares checksums, not just marker presence — catches partial corruption the marker alone would miss.

### Inherited Components (from published research)

1. **MemGPT/Letta page-in page-out** — hot tier stays in context; cold tier pages in on demand.
2. **MemoryOS mid-term tier** — recent sessions get a middle layer between hot and archival.
3. **MemTier five-signal scoring** — ported in full (see Scoring System below). Note: MemTier's own August ablation showed the reranker is near-pass-through of BM25 top-k under aggressive scoping; our composite's value is in promotion/anomaly signals, not retrieval ranking.
4. **Anthropic offline dreaming** — cheap-model pass proposes promotions/demotions; premium model confirms. Run as background job. Anthropic's November data: wiki accuracy 13% → 48%, CL-Bench 0.655 → 0.838. Dreaming prompt rule (Anthropic): tell the agent what memory is for, not how to use it — salience judgment stays with the model, not hardcoded instructions.
5. **Diamant access-frequency promotion** — facts accessed more frequently promote tiers.
6. **arXiv dynamic privilege values** — conflict resolution uses numeric privilege scores per tier.
7. **Hermes canonical precedence** — single global allowlist/precedence model synced across devices.
8. **SoMem tree-structured memory** — self-organizing tree of Markdown nodes; 88.96 LoCoMo, 76.5 LongMemEval-S. Adapted: our checkpoints become tree nodes with parent-child links reflecting topic derivation.
9. **GrepMem zero-indexing** — 95-97% ContextBench with no index build. Adapted: keyword search over flat checkpoints remains the fast path; vector embeddings (Module H) are the slow precise path.
10. **TierMem cheapest-sufficient-evidence routing** (arXiv 2602.17913) — default to fast summary index; escalate to immutable raw-log store only when summary evidence is insufficient. Reduces input tokens 54.1% and latency 60.7% on LoCoMo at 0.851 vs 0.873 raw-only accuracy. Adapted: hot-tier composite score is the default path; full provenance-chain descent is the escalation path.
11. **WikiTrace test-time descent** (KAIST/DeepAuto, Nov 2026) — agent begins with high-level summaries and selectively descends the provenance chain when an insight lacks concrete syntax, originates from a failed run, conflicts with another entry, or triggers an immediate tool error. Adapted: this is the trigger condition for TierMem-style escalation — descent is event-driven, not always-on.
12. **Graphiti bi-temporal timestamps** — every fact carries two clocks: valid_at (when it was true in the world) and transaction/learned_at (when the system learned it), plus invalid_at and expired_at. Resolves relative phrases against episode reference time. Answers "what was true on date X" and "what did we believe on date X."

### Scoring System (MemTier port, v2.1, retained in v3/v3.1/v3.2)

Five signals, weighted composite score per memory fact:

1. **Frequency** — raw access count, decayed by time since last access (half-life 14 days; tune from resurrection logs).
2. **Engagement** — downstream actions triggered by the fact (tool calls, decisions, user confirmations). Each action adds weight proportional to reversibility cost. Cross-instance consensus events add weight across instances, weighted by source trust (see Consensus Poisoning fix).
3. **Recency** — exponential decay from last access timestamp; freshest facts surface first in hot tier.
4. **Cognitive weight** — learned from tool outcomes. Fact's presence correlated with success → weight up; with failure → weight down. Updated by offline dreaming pass. Resurrection hits feed this signal.
5. **Tier boost multiplier** — S+ x4.0, S x3.0, Tier 1 x2.0, Tier 2 x1.0, Tier R x0.1. Applied to composite before ranking.

Composite = (0.25 x frequency + 0.25 x engagement + 0.20 x recency + 0.20 x cognitive_weight) x tier_boost.

Retrieval ranks by composite descending. Ties broken by recency. Score recomputed on every write and on every resurrection hit.

### Novel Additions (v2, retained)

1. **Resurrection logging.** Faded memory re-mentioned → hit records why it mattered (load-bearing vs noise). Feeds signal 4.
2. **Cross-instance consensus.** Two sessions surfacing same memory unprompted = stronger promotion signal than single access count. Feeds signal 2. Now weighted by source trust per instance.
3. **Anomaly gating.** Memory accessed in unfit context → flagged before trusted. Excluded from scoring until human review. Now moves to true quarantine (see v3.2 addition 1).
4. **Versioned bootstrap** — bootstrap line carries revision number for self-healing restore.

### Novel Additions (v3, retained)

1. **Provenance tracking.** Every memory fact carries a chain of custody: which session created it, which tool or search verified it, which human confirmed it, timestamps at each step. Any fact is traceable to origin. Trust assessment becomes evidence-based rather than inferred. Chain capped at 10 entries with compaction (see v3.2 fix 2).
2. **Contradiction surfacing.** When two facts conflict, the system does not silently pick a winner via privilege values. It surfaces both to the human with a one-line summary of each side's evidence and asks for resolution. Humans resolve contradictions better than any scoring formula; the system's job is to notice, not to decide. Batched and ranked by impact (see v3.2 fix 3).
3. **Grace-period retirement.** Faded facts move to Tier R (searchable, excluded from hot scoring) for 30 days before hard deletion. Prevents loss of facts that were temporarily irrelevant.
4. **Session fingerprinting.** Each session ends with a compact hash of its key decisions and outcomes, stored as one memory fact. Future sessions reconstruct "what did we decide about X" from the fingerprint index without re-reading full transcripts.
5. **Bidirectional sync spine with checksums.** Drive ↔ GitHub sync verifies per-file SHA-256 on both ends after every write. Mismatch triggers auto-restore from the higher-version copy and logs the event.

### Novel Additions (v3.1, retained)

1. **Cheapest-sufficient-evidence routing** (from TierMem). Default retrieval path is the hot-tier composite score over summaries. Escalation to full provenance-chain descent happens only when the summary evidence is insufficient for the task at hand. Measured benefit: ~54% fewer input tokens, ~61% lower latency, accuracy drop of only 0.022 on LoCoMo.
2. **Test-time descent triggers** (from WikiTrace). Four explicit conditions fire a provenance descent: (a) retrieved insight lacks the concrete syntax needed for the action, (b) insight originates from a failed run, (c) insight conflicts with another memory entry, (d) insight produces an immediate tool error. Descent is selective and event-driven — never blanket.
3. **Dreaming prompt contract** (from Anthropic). Offline dreaming prompts state what memory is for (continuity, error correction, cross-session reasoning) but never prescribe how to use it. Salience and organization decisions stay with the model. Prompting models to record only failures measurably weakened them; the open-ended contract preserved gains.
4. **Bi-temporal fact stamps** (from Graphiti). Every fact carries valid_at, invalid_at, learned_at, expired_at. Valid time answers world-truth queries; learned time answers belief-state queries. Relative temporal phrases ("last month", "before the pool started") resolve against the episode's reference timestamp, not wall-clock now. Anchor confidence field added (see v3.2 fix 4).

### Heavy-Scenario Fixes (v3.2)

1. **Sweep-heartbeat separation (cascade-failure fix).** The daily integrity sweep writes a timestamped heartbeat file to primary Drive on every run. If the heartbeat is stale beyond twice the interval (12 hours), the system classifies the state as "sweep dead" rather than "all surfaces failed" — these are different failures with different responses. Sweep-dead triggers a re-run attempt before any human escalation. All-four-surface failure still escalates to human, but only after the sweep-dead path is ruled out. Prevents false "ladder undefined" escalations when the detector itself is the broken component.

2. **Provenance-chain compaction (bloat fix).** Chains are capped at 10 entries. When a new entry would exceed the cap, the oldest entries are compacted into a single summary node: "[compacted 1..N]: N entries spanning dates X–Y, topics Z" with the original first and last entries preserved verbatim. Compaction is logged as a provenance event itself. Prevents unbounded storage growth on high-access facts without losing origin traceability.

3. **Ranked contradiction batching (storm fix).** When multiple contradictions surface in one session, they are batched into a single digest ranked by composite-score impact — how much the conflicting facts affect active hot-tier retrieval. The top five are surfaced to the human per session; the remainder queue for subsequent sessions. Prevents contradiction storms from overwhelming the human with fifty simultaneous questions.

4. **Anchor-confidence field (bi-temporal fix).** Every episode auto-generates a reference timestamp from its first message. Each bi-temporal resolution carries an anchor_confidence: HIGH (explicit date in episode), MEDIUM (derived from surrounding context), LOW (fallback to learned_at). LOW-confidence anchors produce a soft flag in the response rather than silent resolution, so the human knows the temporal answer rests on a guess.

5. **Source-trust-weighted consensus (poisoning fix).** Each AI instance carries a source_trust weight derived from its historical accuracy on unprompted memory surfacing (correct vs incorrect promotions over time). Consensus score = instance count x average source trust across participating instances. A single high-trust instance can outweigh three low-trust ones. Prevents a buggy or compromised session from poisoning the promotion signal through sheer repetition.

### Novel Addition (v3.2)

1. **True quarantine surface.** Anomaly-gated facts previously stayed in-file but excluded from scoring — still reachable via explicit query and provenance descent, creating leak paths. In v3.2, flagged facts move to a dedicated fifth copy (quarantine surface) on Drive, excluded from all retrieval paths: hot scoring, keyword search, vector search, and provenance descent. Only explicit human query by fact ID can reach it. Human review either restores to the main spine or confirms retirement. Closes the last edge path between flagged and trusted.

### Standing Response Parameters (Tier S)

1. **Parallel batching** — independent calls in one atomic block at tool max.
2. **Auto-retry dead ends** — five attempts, each a different angle, silent, no user prompt. Under-ten-word dead-end statement if all fail.
3. **Source ranking** — live pages > directories > memory; cite only what changed the answer.
4. **Brevity** — one sentence per finding, numbers as words, zero preamble.

### Integrity Protocol

- Canonical marker: TIER-S-OVERRIDE-ACTIVE-v3.2
- Per-file checksum: SHA-256 of full content on each surface.
- Sweep heartbeat: timestamped file on primary Drive, staleness threshold 12 hours.
- Verification: search all four surfaces for exact marker string; compare checksums; check heartbeat freshness.
- On marker mismatch: restore from highest-version surviving copy.
- On checksum mismatch with matching marker: content corrupted — restore from any copy whose checksum validates.
- On sweep-dead (stale heartbeat, surfaces intact): re-run sweep before escalating.
- On all-four failure after sweep-dead ruled out: escalate to human; ladder undefined until restored.
- Daily sweep: 06:00 AEST, automation ID 5f00b4db, logs PASS/FAIL to Drive.

### Open Questions

- Should resurrection logs themselves be tiered?
- Cross-instance consensus requires shared telemetry — privacy boundary?
- Anomaly gating false-positive rate under load?
- Optimal decay half-life — 14 days is initial guess, tune from resurrection logs.
- Should cognitive weight updates require premium-model confirmation like promotions?
- Tier R retention: 30 days enough, or should it be configurable per fact category?
- Session fingerprint granularity: per-session vs per-topic?
- Provenance chain length cap — 10 is initial guess; tune from compaction frequency.
- Cheapest-sufficient-evidence: how to define "insufficient" programmatically vs judgment call?
- Bi-temporal stamps: valid_at vs learned_at divergence — when do they matter enough to surface?
- Source trust: how is the initial trust weight seeded for a new instance?
- Quarantine surface: should it be a fifth Drive copy or a separate repo path?
- Sweep heartbeat: should staleness threshold be adaptive to sweep runtime?
